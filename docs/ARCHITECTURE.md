## 核心模块说明

### 1. Kernel（微内核）

**职责**：
- 消息路由（Broker）
- Node 注册和发现（Registry）
- 健康检查（Health Checker）
- 消息序列号检查（Sequence Checker）
- 背压控制（Backpressure Controller）
- 监控和告警（Monitoring Service）

**关键特性**：
- ✅ ZeroMQ 高性能消息传递
- ✅ 消息序列号检查，防止乱序
- ✅ 背压控制，防止系统过载
- ✅ 实时监控和健康检查

---

### 2. Agent（智能体）

**职责**：
- 任务编排（Orchestrator）
- 多 Agent 并行执行
- Doom Loop 检测
- Skill 调用
- 记忆管理

**关键特性**：
- ✅ 多种 Agent 类型（Primary, Explore, Plan, GeneralPurpose）
- ✅ Plan-Execute 模式
- ✅ 子 Agent 异步执行
- ✅ 消息确认和重试（ACK）

---

### 3. Tools（工具集）

**职责**：
- Bash 执行
- 文件操作（Read/Write/Edit）
- 搜索（Grep/Glob）
- Git Checkpoint
- 自动验证

**关键特性**：
- ✅ 统一工具接口
- ✅ 安全执行环境
- ✅ 自动验证循环
- ✅ Git 快照和回滚

---

### 4. Memory（记忆系统）

**职责**：
- L0 工作记忆（内存）
- L1 短期记忆（向量库）
- L2 长期记忆（持久化）
- 记忆检索（Recall）

**关键特性**：
- ✅ 三层记忆架构
- ✅ 冷热分层（Heat Score）
- ✅ 滑动窗口更新
- ✅ Dream 整理机制

---

### 5. Sampler（LLM 后端）

**职责**：
- 多 Provider 支持
- 自动路由和 Fallback
- 连接池和限流
- 流式响应处理

**关键特性**：
- ✅ OpenAI/Claude/DeepSeek/Qoder 支持
- ✅ Token Bucket/Leaky Bucket 限流
- ✅ 连接池管理
- ✅ 自动重试策略

## 数据流

### 消息传递流程

```
用户输入
    │
    ▼
Agent 接收
    │
    ├─→ 工具调用 → 工具执行 → 返回结果
    │
    ├─→ LLM 调用 → Sampler → 流式响应
    │
    └─→ 子 Agent 启动 → 并行执行 → 结果聚合
                                    │
                                    ▼
                                用户输出
```

### 消息总线流程

```
Node A 发送消息
    │
    ├─→ 添加序列号（Sequence Manager）
    │
    ├─→ 发送到 Kernel（DEALER Socket）
    │
    ▼
Kernel 接收
    │
    ├─→ 检查序列号（Sequence Checker）
    │
    ├─→ 路由消息（Broker）
    │   │
    │   ├─→ Topic 匹配
    │   │
    │   └─→ 批量发送（Broadcast Optimization）
    │
    ├─→ 检查背压（Backpressure Controller）
    │
    ├─→ 记录指标（Metrics Collector）
    │
    └─→ 发送确认（ACK）
```

## 关键设计决策

### 1. 为什么使用 ZeroMQ？

**优点**：
- ✅ 高性能（比 HTTP 快 10x）
- ✅ 多种模式（REQ/REP, PUB/SUB, DEALER/ROUTER）
- ✅ 自动重连
- ✅ 跨语言支持

**缺点**：
- ⚠️ 不保证消息顺序（我们用序列号解决）
- ⚠️ 不保证消息可靠（我们用 ACK 解决）

### 2. 为什么用三层记忆？

**设计理由**：
- **L0 工作记忆**：当前任务上下文，快速访问
- **L1 短期记忆**：会话级记忆，语义检索
- **L2 长期记忆**：持久化存储，跨会话共享

**效果**：
- ✅ 平衡性能和容量
- ✅ 支持长期学习
- ✅ 自动冷热分层

### 3. 为什么需要背压控制？

**问题**：
- 消息生产速度 > 消费速度
- 队列满导致阻塞
- 系统过载导致崩溃

**解决方案**：
- ✅ 自动检测队列水位
- ✅ 动态调整发送速率
- ✅ 保护系统稳定性

## 扩展性设计

### 1. 插件化工具

```rust
// 定义新工具
impl Tool for MyTool {
    fn name(&self) -> &str { "my_tool" }
    fn execute(&self, args: &Value) -> Result<Value> {
        // 自定义逻辑
    }
}

// 注册到 Kernel
kernel.register_tool(Box::new(MyTool::new()))?;
```

### 2. 自定义 Agent

```rust
// 定义新 Agent
impl Node for MyAgent {
    async fn run(&mut self) -> Result<()> {
        // 自定义逻辑
    }
}

// 启动 Agent
kernel.spawn_node(MyAgent::new())?;
```

### 3. 自定义 Provider

```rust
// 定义新 Provider
impl Provider for MyProvider {
    async fn sample(&self, request: SampleRequest) -> Result<SampleResponse> {
        // 自定义逻辑
    }
}

// 注册到 Router
router.register_provider("my-model", Box::new(MyProvider::new()))?;
```
